- 0.2.0 (2026-09-05) — tenant-ready registry (#4): `enabled:` field, engine-injected per-service identity env, safe `make test`, stale-plist pruning, content-aware deploy diff, unified generation pipeline, wrapper fallback chain.
  - **Tenant-ready registry (P2)**: `GenerateLaunchdPlist` now injects `HOME_STACK_SELF_NAME`, `HOME_STACK_SELF_HOST` (the rendered FQDN, or empty when the service has no `subdomain`/`host` or resolves to a wildcard), `HOME_STACK_SELF_URL` (`https://<host>` or empty), and `HOME_STACK_DATA_DIR` into every managed service's plist, alongside the existing `HOME_STACK_PROFILE` pin — computed from the service's own registry entry and never overridable from it (`Validate` already rejects `HOME_STACK_*` in a service's `env:`). `HOME_STACK_DATA_DIR` honors a `HOME_STACK_CONFIG_DIR` override the same way `GenerateSystemDaemonPlist` already did. Added a `home_stack_service_url` helper to `lib/common.sh` that reads a service's `url` straight out of `catalog.json` (the engine-computed `Service.RoutableURL`) rather than recomposing a hostname in the shell. Each of `run-pocket-id.sh`, `run-tinyauth.sh`, and `run-hermes.sh` now resolves its **own** URL/data-dir as: the injected `HOME_STACK_SELF_URL`/`HOME_STACK_DATA_DIR` if set, else `home_stack_service_url`/`$HOME_STACK_CONFIG_DIR/data/<name>` (still registry-authoritative, never a profile variable), else exit 78 naming both sources — closing a rollout hazard where `hs restart` (`launchctl kickstart -k` re-execs under the *existing* environment; launchd only re-reads a plist on `bootstrap`) or a reboot before the next `install-launchd.sh --load` would otherwise crash-loop these services under KeepAlive the instant the injected variable was required with no fallback. `run-tinyauth.sh` and `run-hermes.sh` separately resolve Pocket ID's URL (for OIDC) the same way. Deleted the now-dead `HOME_STACK_ENABLE_*` flags, `HOME_STACK_POCKET_ID_SUBDOMAIN`/`HOME_STACK_TINYAUTH_SUBDOMAIN`, `HOME_STACK_PHASE_A_CADDY_PORT`/`HOME_STACK_PHASE_B_CADDY_PORT`, and `HOME_STACK_DEV_DOMAIN` from every profile, fixture, and template; the `hs app` stub (`cmd_app_add`) is removed, and `hs`'s dispatch now refuses any unrecognized first-level command (e.g. `hs app add`) with usage and exit 2 before the `<service> <command>` fallback is attempted, instead of forwarding it to `service-launchd.sh` as a bogus action/target pair.
  - **Registry `enabled:` field**: a service may now set `enabled: false` (default `true`) to be registered, validated, and inventoried without being deployed — the engine emits no Caddy route and no launchd plist for it in any generation path (`GenerateCaddyfile` and the unified `desiredArtifacts`/`writeArtifacts` pipeline shared by `syncSystem`, `registry.go` `Diff`, and `registry.go` `Apply`), consolidated behind one new `Service.generatesAgentPlist()` helper instead of three copies of the same type-based skip check. `Validate` rejects `enabled: false` outright on a `type: system` service, on `admin`, and on the auth broker while an enabled service still needs it (naming the dependents) — each would otherwise silently break the stack with nothing downstream that notices. `catalog.json` still carries the service with `"enabled": false` and now also carries a per-service `"url"` field computed from the new `Service.RoutableURL`, present only for a routable, enabled, non-wildcard service; the Portal catalog projection still lists a disabled service with `url: null` and `launchable: false` (schema and `lifecycle` enum unchanged), and `aggregatePortalState` no longer lets a disabled service's own "unknown" state drag the Portal-wide `overall_state` to "degraded". Admin skips all launchd/port/route/http checks for a disabled service and reports it under the new `"disabled"` overall state (its own bucket in `/api/overview`'s counts) — unless it is disabled but not yet pruned by `install-launchd.sh`, in which case `collectServices` still reports its launchd state, an info incident names it, and it gets exactly a `service.stop` action (`app.js`'s `sig()` takes an explicit `disabled` flag so this doesn't regress a merely-not-yet-installed *enabled* service).
  - **Stale plists are now pruned on sync/apply**: `syncSystem` and `registry.go`'s `Apply` previously only ever wrote plists, never removed one for a service dropped from the registry or newly disabled — so `install-launchd.sh`'s own prune step, which keys off what already exists in the launchd bundle dir, could never see it and never uninstall it. Both now delete any `<identifier-prefix>.home-stack.*.plist` no longer in the desired set (never touching the `daemons/` subdirectory or a file outside the prefix namespace) and log "Removed stale plist for `<name>`", via one idPrefix-scoped `agentPlistFilename`/`plistServiceName` helper shared by `diffPlists` and `pruneStalePlists` so a leftover plist from a different identifier prefix can no longer collide with a same-named service. `Apply` now also generates and prunes the daemon plist (previously agent plists only), and `Diff` now includes the daemon plist in its comparison and validates `HOME_STACK_IDENTIFIER_PREFIX` up front like `Apply`/`syncSystem` instead of reading it unchecked inside its loop.
  - **`diffPlists` is content-aware**: it previously matched plists by name only, so a service whose generated content changed (args, env, upstream) with no change in its file's presence reported no diff at all — `hs deploy --preview` was blind to it. It now reads the existing file and compares bytes, reporting `Changed` ("Would update plist for `<name>`") when they differ.
  - **`make test` and three shell tests no longer touch the source tree**: the `test` target built `portable/home-stack/admin/home-stack-admin` in place, overwriting the production binary launchd resolves with whatever branch happened to be checked out; it now runs `go build -o /dev/null .` as a pure compile check (nothing consumes that binary), and `make build-admin` owns the production path exclusively. `tests/identifier-prefix-flow.test.sh`, `tests/install-launchd-e2e.test.sh`, and `tests/service-lifecycle.test.sh` ran `hs sync` and stubbed `reload-caddy.sh` directly against the real checked-out bundle (restoring the stub from a backup afterwards); all three now stage an isolated copy of `portable/`, `profiles/`, and `templates/` (excluding the ~300MB gitignored `bin/` too) via a new shared `tests/lib/stage.sh` helper (`home_stack_stage_repo`) instead of three drifting copies of the same rsync. `tests/source-tree-guard.test.sh` now also flags any test that calls `rsync -a` directly instead of going through that helper, in addition to its existing checks that the production binary path and `$ROOT_DIR`'s `hs`/`reload-caddy.sh` are never written to directly.
  - **Plan realignment (docs only)**: audited every planned workstream against implementation truth (`docs/PLAN.md`), re-sequenced `docs/ROADMAP.md`, archived the implemented Phase 1 design notes to `docs/attic/specs/`, and reconciled README, STATUS, ARCHITECTURE, SECURITY, SERVICE_INTERFACE, GOVERNANCE, AGENTS, and INDEX with each other. - 0.1.0 (2026-09-04) — identity layer, Hermes operator baseline, launchd race retirement, profiles & portability. Tagged at the merge of `feat/tailnet-identity-layer` (#2).
  - **Hermes update and gateway ownership**: documented the reviewed-update procedure (back up config, run the pinned installer/`hermes update` against a reviewed commit, migrate config schema, converge the managed environment to the upstream committed lock). Documented installing and verifying the official profile-aware `ai.hermes.gateway` LaunchAgent for the internal messaging/cron worker instead of generating a competing Home Stack plist.
  - **Hermes Basic credential rotation procedure**: documented regenerating only the server-side scrypt hash from the existing Apple Passwords/iCloud website credential, restarting only Hermes, and verifying that Autofill opens the HTTPS dashboard afterward without exposing or storing server-side plaintext.
  - **Hermes plan simplified around native capabilities**: the authenticated operator may use arbitrary user CLIs and coding harnesses without a bespoke wrapper/permission layer; worktrees, profiles, and custom coordination are now adopted only for concrete concurrency or isolation needs. Corrected the iPhone contract: `goncharik/hermes-mobile` is a community client of the official dashboard API, currently requires Basic auth, stores its session locally in the device Keychain, and leaves its optional third-party push path off pending review.
  - **Hermes operator baseline documented**: a staged pattern for isolating the live agent environment, configuring explicit provider/auxiliary privacy and cost routing, gating memory/skill writes, bounding delegation, and keeping unattended messaging/cron/webhook/computer-use surfaces disabled by default. Documented Hermes' native approval-detector limitation (the smart-approval reviewer only runs for commands its built-in detector already flags).
  - **Hermes process-environment isolation**: `run-hermes.sh` now resolves the shared profile and then execs the tool-capable agent under a clean allowlist, preventing unrelated Home Stack secrets from becoming ambient agent authority. The wrapper test proves required Hermes Basic/OIDC inputs pass while fake Admin/Cloudflare credentials, ambient sentinels, and every `HOME_STACK_*` variable are absent. Added a staged authority/operations contract for personal, remote-operator, coding, CLI, gateway, and automation use.
  - **launchd reload race retired**: `bootout` is asynchronous, and every script that bootstrapped straight after it could kill a service and then fail to restart it ("Bootstrap failed: 5"). A shared `home_stack_wait_label_gone` helper polls teardown to completion; loaded-and-unchanged services now restart via `kickstart -k` (no unload, no race); `install-launchd.sh --load` converges: it still guarantees every service ends up loaded, but a running service whose plist is byte-identical is left alone rather than bounced (a rebuilt binary behind an unchanged plist therefore needs an explicit `hs restart`). `service-launchd.sh` restart drops its `sleep 1` for the real fix, and now loads its own environment so it works standalone, not only through `hs`. Guarded by `tests/launchd-race-guard.test.sh`.
  - **Tailnet-first identity layer** (staged; cutover is operator-run): new `auth:` registry field (`none`/`tailnet`/`sso`/`tailnet-or-sso`) makes authentication opt-in per service, emitting one fixed Caddy block per value in the same closed-enum idiom as `proxy_identity`. `tailnet` uses the caddy-tailscale plugin's `tailscale_auth` for genuinely zero-click access — it resolves the peer through the local tailscaled WhoIs API and needs no tsnet node, no API token, and no extra process. `sso` forwards to tinyauth, which brokers login and federates Pocket ID passkeys (and LDAP later); `tailnet-or-sso` chains both, with a `remote_ip` matcher choosing the lane while `tailscale_auth` still does the authorizing. Pocket ID and tinyauth join the registry as loopback-bound launchd services. Absent `auth:` is proven byte-identical to prior output, so existing routes are untouched.
  - **Builds target the host's real architecture**: the Go toolchain and Homebrew are both Intel under Rosetta on this Apple Silicon host, so every home-stack binary — including the live ingress — was x86_64 and translated. The Makefile now derives `GOARCH` from `uname -m` (Linux CI unaffected) and sets `CGO_ENABLED=1` explicitly on Darwin, which is load-bearing: Go silently disables cgo when `GOARCH` differs from the toolchain's, which would have switched the admin service to Go's pure resolver and broken its MagicDNS health checks.
  - **Caddy build recipes unified**: `bootstrap.sh`, the Tart image, the Linux test image, and RUNBOOK each built a different plugin set (`caddy-security` appeared in two, and in neither the live binary nor RUNBOOK). All now build Cloudflare DNS + Tailscale for the native arch. Fixed `profile-portability.test.sh`, which hard-failed `caddy validate` against any stock `caddy` on `PATH` and could never have passed anywhere — the Cloudflare provider rejects placeholder tokens at provision time — so it now prefers a plugin-capable binary and uses `adapt`.
  - **Hermes**: version docs corrected to track the actually-installed checkout rather than a stale reference; `run-hermes.sh` gained pass-through for the build's generic self-hosted OIDC plugin, left inert until an OIDC client is registered and deliberately additive so the existing password provider remains a break-glass path.
  - **Portal v2 data boundary**: added host-gated, read-only catalog and live-status projections for the static `home-portal` app, exact Caddy routes at `/.well-known/home-stack/catalog.json` and `status.json`, canonical JSON Schemas with executable projection tests, and CI/update automation. The projections are versioned and deliberately omit infrastructure paths, process identifiers, diagnostics, actions, and secrets; all Admin/control-plane routes remain authenticated.
  - **Official Hermes Agent integration**: added and deployed a managed Hermes registry entry, foreground wrapper, port/profile contract, hashed native dashboard auth mapping, stable session-secret requirement, Caddy Host/Origin compatibility mode for HTTPS/WebSockets, generator/wrapper/security tests, and the documented Tailnet-only authenticated native-protocol exception. Also repaired the private loopback `hs deploy` transport so reviewed registry previews work from the CLI.
  - **Docs consolidated**: session logs, dated plans, and the original roadmap moved to `docs/attic/` with a README stating they are provenance, not guidance; live docs updated to point there. Documented two intentional designs that read as mistakes: OpenChamber owning the `opencode.` hostname (it is OpenCode's web interface) and the engine-vs-`render-caddyfile.sh` generation boundary.
  - **Admin webapp split into editable assets**: the 25KB single-template blob (with 5,000-character lines) is now `index.html` + `app.css` + `app.js`, all still `go:embed`ed and served behind the same auth from a new allowlisted `/assets/` route — zero build step, but reviewable diffs. Extraction was verified byte-identical to the committed original before formatting, and the reformat proven code-preserving. Template tests now assert against all assets combined so the split cannot silently drop a check.
  - **Caddy runtime logs at WARN**: the generated Caddyfile sets a global log level so admin-API health polling and TLS maintenance chatter no longer bury real errors in the daemon log (a previous log hit 33MB, mostly INFO noise). OpenChamber's per-request stdout logging has no CLI off-switch; rotation contains it.
  - **One launchd generation pipeline**: the Caddy LaunchDaemon plist is now generated by the engine (`launchd/daemons/`) alongside agent plists, golden-tested per fixture; deleted the bash-rendered plist template it replaces (verified byte-equivalent semantics against the installed daemon) and four orphaned agent plist templates with no callers. Snapshot/idempotency/portability tests cover the daemons subtree.
  - **Admin action allowlists derive from the registry**: the three `service.*` actions consult `lifecycle:` (`managed` = operable; `external`/`custom`/unset = route-only; `type: system` = reload-only; scheduled tasks get start/restart but no stop; admin itself is restart-only from its own UI). Replaces two hardcoded service-name lists that made registry additions inoperable from the webapp. `Registry.Validate` now rejects unknown lifecycle values; UI buttons and API enforcement share one derivation.
